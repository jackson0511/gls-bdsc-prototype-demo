1. Tổng quan đề xuất

PWMS (AppSheet / bảng trong GLSPWMS) là nguồn dữ liệu kho · NCC · sản phẩm · chứng từ. TMS (Quản lý xe) gọi các API dưới đây để seed lần đầu, đồng bộ định kỳ, và đẩy phiếu BD/SC kèm vật tư sang bộ phận mua hàng.

#APIHướngBảng nguồn (Excel)Mục đích
1 Master sync PWMS → TMS Supplier, Product_SERI, Object, Product, Repair_Category, Storage_Type Đồng bộ danh mục master
2 Purchase sync PWMS → TMS Repair_Card / Repair_Transaction (+ chứng từ liên quan theo mã phiếu) Kéo dữ liệu mua hàng theo mã phiếu BD/SC hoặc khoảng thời gian
3 Send order TMS → PWMS Ghi nhận phiếu trên PWMS để MH nhập liệu đúng mã Gửi phiếu BD/SC + vật tư dự kiến
4 Storage sync PWMS → TMS Storage_Transaction, Storage_Card Giá VT · thời điểm xuất kho
5 Fuel sync PWMS → TMS Fuel_Card Thông tin dầu nội bộ
Bốn tình huống sync cần hỗ trợ trên mọi API đọc (1) Đồng bộ tất cả · (2) Đồng bộ chỉ định (bảng / mã phiếu / mã phiếu kho) · (3) Đồng bộ theo khoảng updated_from → updated_to (đồng bộ theo khoảng sau lần chạy đầu) · (4) Chỉ bản đang áp dụng (active_only=true / ap_dung) hoặc lấy cả ngưng dùng.

2. Quy ước chung

Base URL (đề xuất)

https://{pwms-host}/api/v1

Auth: Authorization: Bearer {token} · Content-Type: application/json

Tham số dùng chung (query / body)

Tham sốÝ nghĩa
modeALL | RANGE | BY_KEY
updated_from / updated_toISO-8601 · lọc ngay_cap_nhat / thời gian chứng từ
active_onlytrue = chỉ ap_dung=true · false = tất cả
page / page_sizePhân trang (mặc định 200, tối đa 1000)
cursorTuỳ chọn thay page khi dataset lớn
Gợi ý vận hành Lần đầu: mode=ALL (có thể tách theo bảng). Các lần sau: mode=RANGE với updated_from = last_synced_at (mốc đồng bộ lần trước) lần sync trước trên TMS. Phiếu MH: ưu tiên BY_KEY theo mã phiếu TMS khi người dùng bấm «Đồng bộ mua hàng».

3. API #1 — Đồng bộ master

Một endpoint nhận tên bảng (hoặc danh sách bảng) để trả về bản ghi master từ PWMS. Hỗ trợ get all, get theo khoảng ngày cập nhật, active only / tất cả.

POST/api/v1/masters/sync
Supplier Product_SERI Object Product Repair_Category Storage_Type
  • ALL — toàn bộ bản ghi (một hoặc nhiều bảng)
  • BY_KEY — chỉ định bảng + danh sách id / mã
  • RANGE — theo ngay_cap_nhat trong khoảng
  • active_only — chỉ bản đang áp dụng

Request — đồng bộ tất cả master (lần đầu)

{
  "mode": "ALL",
  "tables": [
    "Supplier",
    "Product_SERI",
    "Object",
    "Product",
    "Repair_Category",
    "Storage_Type"
  ],
  "active_only": false,
  "page": 1,
  "page_size": 500
}

Request — chỉ một bảng + đang áp dụng

{
  "mode": "ALL",
  "tables": ["Product"],
  "active_only": true,
  "page": 1,
  "page_size": 200
}

Request — theo khoảng ngày cập nhật (RANGE)

{
  "mode": "RANGE",
  "tables": ["Supplier", "Product", "Storage_Type"],
  "updated_from": "2026-09-01T00:00:00+07:00",
  "updated_to": "2026-10-01T23:59:59+07:00",
  "active_only": false,
  "page": 1,
  "page_size": 200
}

Request — chỉ định khóa (BY_KEY)

{
  "mode": "BY_KEY",
  "tables": ["Object"],
  "keys": {
    "Object": ["50E-65517", "51C-29273"]
  },
  "active_only": false
}

4. API #2 — Đồng bộ dữ liệu mua hàng

Kéo dữ liệu mua hàng / sửa chữa đã nhập trên PWMS về TMS. Ưu tiên truyền mã phiếu BD/SC từ TMS; sau lần sync đầu có thể lấy phần mới theo khoảng ngày giờ.

POST/api/v1/purchase/sync
Repair_Card Repair_Transaction Storage_Card (liên quan)

Request — theo mã phiếu TMS (khi cần)

{
  "mode": "BY_KEY",
  "order_codes": ["RO-2026-1002", "RO-2026-3388"],
  "include": ["header", "lines", "issue_docs"],
  "active_only": false
}

Request — theo khoảng thời gian (sau lần đầu)

{
  "mode": "RANGE",
  "updated_from": "2026-09-28T00:00:00+07:00",
  "updated_to": "2026-10-01T18:00:00+07:00",
  "include": ["header", "lines"],
  "page": 1,
  "page_size": 100
}

Request — lấy toàn bộ (lần đồng bộ đầu)

{
  "mode": "ALL",
  "include": ["header", "lines"],
  "page": 1,
  "page_size": 200

6. API #4 — Đồng bộ Storage (giá & giờ xuất kho)

Lấy dữ liệu từ Storage_Transaction và Storage_Card phục vụ kiểm tra giá vật tư và thời điểm xuất kho.

POST/api/v1/storage/sync
Storage_Transaction Storage_Card

Request — theo khoảng (sau lần đồng bộ đầu)

{
  "mode": "RANGE",
  "entities": ["Storage_Transaction", "Storage_Card"],
  "updated_from": "2026-09-20T00:00:00+07:00",
  "updated_to": "2026-10-01T23:59:59+07:00",

    "loai": ["XUAT", "XUAT_SUA_NGOAI"],

  "page_size": 500

8. Luồng gọi đề xuất

Không mô tả ánh xạ — chỉ thứ tự query / đồng bộ và gửi phiếu.

Lần đồng bộ đầu Master ALL → Storage ALL (tuỳ chọn) → Fuel ALL (tuỳ chọn) → lưu mốc đồng bộ last_synced_at trên TMS.
Hàng ngày / khi cần Master RANGE · Storage RANGE · Fuel RANGE · Send order khi duyệt · Purchase BY_KEY khi KTV đồng bộ MH.
Tình huốngmodeTham số chính
Đồng bộ tất cảALLtables / entities · page
Đồng bộ chỉ địnhBY_KEYkeys · order_codes · tables
Đồng bộ khoảng thời gianRANGEupdated_from · updated_to
Chỉ đang áp dụngmọi modeactive_only=true
Lấy cả ngưng dùngmọi modeactive_only=false
